# CloudBTL Studio

CloudBTL Studio is a long-term direction, not the immediate build target.

## Thesis

PowerPoint is a legacy artifact for a world where materials were static, fixed-ratio, and file-based. BTL materials now need to work across mobile, tablet, desktop, embedded web, and AI workflows.

That requires a different editor:

- Responsive by default
- Web-native output
- Section-based structure
- Designed for interaction, measurement, and iteration
- AI-readable content model
- Built-in DeckLens instrumentation

## Product Direction

Studio should eventually let teams create web proposals directly instead of converting old files.

Core concepts:

- Sections instead of slides
- Responsive layout blocks instead of fixed canvases
- Components for CTA, form, pricing, case study, media, table, comparison, and timeline
- Built-in tracking names
- Preview across screen sizes
- Version comparison
- AI rewrite and restructuring
- Export to static HTML

## Boundary

Do not build Studio until DeckLens and Convert are useful.

Sequence:

1. DeckLens proves measurement value.
2. Convert brings existing materials into the web-native flow.
3. Rooms proves delivery and buyer engagement.
4. Studio becomes the native creation surface.

## Open Questions

- Should Studio be block-based, canvas-based, or hybrid?
- How much visual fidelity do proposal teams need versus responsive behavior?
- Should Studio export pure static HTML or a runtime bundle?
- Which component model works best for AI editing?
- How do we keep it simpler than Webflow but more proposal-native than slides?
